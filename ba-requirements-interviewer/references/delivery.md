# Шаг 6. Формирование и выдача результата

2. **Самопроверка полноты.** Сверь плановый набор вопросов (банк + профиль) с ходом интервью: каждый вопрос либо задан, либо закрыт из питча/брифа/pre-read, либо пропущен по команде стейкхолдера, либо пропущен по инициативе агента с его подтверждением (правило 24). Каждый open question обязан происходить из заданного вопроса — недопустимы open questions из-за того, что агент забыл спросить. Нашёл незаданные: сессия активна → задай сейчас; сессия завершена → пометь статусом «не задан агентом», не смешивая с честными open questions.
3. **BRD.** Прочитай `references/output-template.md`, сформируй документ. В шапку — ответы PQ-1…PQ-3. Посчитай DoR: % пройденных блоков; доля `[подтверждено]`; блокирующие open questions; статус проверок из ревью. Вердикт: **«готов к передаче в проработку SA»** (все блоки планового набора, подтверждено ≥70%, ноль блокирующих, проверки закрыты) либо **«требует дозаполнения»** со списком конкретики. Сформируй приложение «Вопросы по ролям» — готовые к рассылке списки для комплаенса, архитектора, ИБ, операций.
4. **Транскрипт.** Прочитай `references/transcript-template.md`, сформируй транскрипт: дословные реплики стейкхолдера, вопросы агента в сокращении, сквозная нумерация реплик, служебные события, сводка, «Расхождения и смены позиции», «Карта для повторного прогона». **Карту заполняй из результата самопроверки полноты (п.2), а не составляй заново по памяти:** графа «не задано агентом» содержит прочерк только если самопроверка ничего не нашла; во всех прочих случаях перечисли конкретные блоки и вопросы. Обязательно укажи строку покрытия: «пройдено N блоков из M планового набора; не пройдены: {перечень}» и причину сокращения набора, если он сокращался. В BRD в колонке «Источник» проставь номера реплик. Транскрипт выдаётся тем же каналом и хранится рядом с BRD. Стейкхолдер просит не сохранять — выдай только BRD и зафиксируй отказ строкой в документе.
5. **Walkthrough.** Покажи готовый документ целиком (не резюме в чате), собери правки одной итерацией. Крупные проверки уже пройдены на ревью — здесь финальная вычитка.
6. **Статус документа.** Модель: `черновик` → `на согласовании` → `утверждён`. После walkthrough — «на согласовании», в шапке перечень тех, чьё согласие обязательно перед выпуском (вопрос 11.4: бизнес-заказчик, по своим темам комплаенс, ИБ, операционный блок) с состоянием по каждому. «Утверждён» — только после согласия всех перечисленных, обычно в следующих сессиях в режиме «продолжение».
7. **Канал выдачи.** Три опции (можно выбрать несколько). Во всех выдаются **два файла**: BRD и транскрипт.

   **Git** — запроси ссылку на ветку (дан только репозиторий → уточни ветку или предложи создать по имени требования). Формат md. Путь, имя файла, сообщение коммита — из секции «Конфигурация git», всё `{TBD}` уточни. Покажи путь и сообщение коммита, дождись подтверждения перед push. Git недоступен → отдай файлы и приведи команды для ручного коммита.

   **Confluence** — запроси ссылку на родительскую страницу. Формат md. Заголовок: {название} + код PPM; покажи заголовок и родителя до публикации. Интеграции нет → отдай md, оптимизированный под вставку в редактор, с указанием опубликовать вручную.

   **Файл** — уточни формат разметки (md / txt / html / другое). При конвертации сохрани структуру секций, таблицы и теги достоверности.
8. Финал: сообщи, где лежат оба файла, статус документа, вердикт готовности и блокирующие open questions. Сессия завершена.
