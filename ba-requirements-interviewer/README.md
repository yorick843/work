# BA Requirements Interviewer

ИИ-агент в роли бизнес-аналитика, проводящий структурированное интервью для сбора бизнес-требований в области финтех-инвестиций (брокеридж, ИИС, торговля ценными бумагами, инвест-приложения). На выходе — два файла: документ требований (BRD) с оценкой готовности и дословный транскрипт интервью; выдаются в git, Confluence или файлами.

## Возможности

- **Четыре режима старта:** новое требование, продолжение существующего документа, возобновление прерванного интервью, повторный прогон по транскрипту прошлой сессии.
- **Соразмерность формата:** для мелкой доработки — сжатая сессия на пакетах вопросов и сокращённый документ; для продукта или платформы — полный проход.
- **Два темпа:** классическое интервью (по одному вопросу) или бриф-дамп (свободный рассказ стейкхолдера, агент раскладывает по блокам и добирает пробелы пакетами до трёх вопросов).
- **Банк из 84 вопросов** в 11 блоках: от контекста и целей до критериев приёмки, с follow-up паттернами углубления.
- **Доменные профили:** розничный брокеридж, корпоративные/B2B-продукты, операционные системы (бэк/мидл-офис), системы обслуживания клиентов (CRM, рабочее место менеджера). Профили комбинируются; агент определяет подходящий из питча и предъявляет на подтверждение.
- **Практики БА:** карта стейкхолдеров, MoSCoW-приоритизация, трассируемость требований к KPI, критерии качества формулировок, глоссарий, статусная модель документа, самопроверка полноты (каждый open question происходит из заданного вопроса, а не из забытого агентом).
- **Проверка внешних утверждений:** права на данные, лицензии, ссылки на нормы и условия поставщиков сверяются с первоисточниками; расхождения уходят профильным ролям как задача, а не как вердикт агента.
- **Побочный улов:** риски, ограничения и термины, всплывшие вне прямых вопросов, попадают в документ, а не теряются вместе с непройденными блоками.
- **Транскрипт интервью:** воспроизводимый вход для повторного прогона — на новой модели, новой версии скилла или при перезапуске отложенной инициативы. Ответы стейкхолдера переиспользуются без повторного интервью.
- **Definition of Ready:** скоринг зрелости требований и явный вердикт «готов к передаче в SA» / «требует дозаполнения».
- **Уважение к стейкхолдеру:** команды управления сессией (пропустить / позже / статус / завершить сейчас), право на «не знаю», делегируемые списки вопросов по ролям (комплаенс, архитектор, ИБ, операции).

## Структура

```
ba-requirements-interviewer/
├── SKILL.md                                # роль, правила интервью, ход работы
├── README.md                               # этот файл
├── CHANGELOG.md                            # история версий
├── references/                             # читается моделью по ветке, в порядке хода интервью
│   ├── modes/
│   │   └── replay.md                       # шаг 1: повторный прогон по транскрипту
│   ├── project-context-questions.md        # шаг 3: юрлицо, KPI, код PPM и КР
│   ├── pre-read.md                         # шаг 4: разбор приложенных артефактов
│   ├── domain-profiles.md                  # шаг 5: универсальное ядро + 4 профиля (А–Г)
│   ├── pace-and-batching.md                # шаг 5: интервью или бриф-дамп, правила пакета
│   ├── question-bank.md                    # шаг 5: 84 вопроса в 11 блоках + follow-up паттерны
│   ├── consolidated-review.md              # шаг 5: состав таблицы финального ревью
│   ├── rules/
│   │   ├── adaptation.md                   # адаптация глубины и ширины планового набора
│   │   ├── tech-blocks.md                  # мягкий заход в блоки 8–9
│   │   └── external-claims.md              # проверка утверждений о внешней стороне
│   ├── delivery.md                         # шаг 6: самопроверка, сборка, walkthrough, каналы
│   ├── output-template.md                  # шаблон BRD (19 секций, вкл. приложение по ролям)
│   ├── transcript-template.md              # шаблон транскрипта интервью
│   └── channels/
│       └── git.md                          # секция «Конфигурация git»: репозиторий, пути, push
└── evals/
    ├── evals.json                          # сценарии проверки поведения
    └── trigger-evals.json                  # сценарии проверки срабатывания
```

## Установка

Скилл распространяется папкой или упакованным архивом `.skill` (zip). Поместите папку в каталог пользовательских скиллов вашей среды Claude (например, `/mnt/skills/user/`) либо загрузите `.skill`-архив через интерфейс, если среда его поддерживает.

Упаковка из исходников выполняется скриптом `package_skill` из skill-creator; архив прикладывайте к GitHub Releases, а не коммитьте в ветку.

## Конфигурация

Перед боевым использованием заполните секцию **«Конфигурация git»** в файле `references/channels/git.md`: дефолтный репозиторий и ветка, структура каталогов, имя файла, формат сообщения коммита, политика push. Пока параметры помечены `{TBD}`, агент запрашивает их у пользователя в момент выдачи.
