# Режим «что изменилось» — две версии BRD

Версия ядра: 2

Файл общий для скиллов `brd-digest-*`: копии побайтово одинаковы.

## Содержание

1. Когда включается
2. Сравнение
3. Как подать изменения
4. Что считать шумом
5. Ограничения

## 1. Когда включается

Пользователь дал две версии BRD (старую и новую) или выжимку по старой версии и новую BRD. Выжимка строится по новой версии как обычно; раздел «Что изменилось» ставится сразу после шапки. Если дана только новая версия, режима нет.

Если дана старая выжимка, а не старый BRD, сравнить версии по ID нельзя: попроси старый BRD. Причина: сравнение выжимки с BRD смешает изменения источника с решениями о том, что опускать.

## 2. Сравнение

Запусти `python scripts/brd_tools.py diff <старый BRD> <новый BRD>` (флаг `--json` даёт структурированный вывод). Скрипт сравнивает по ID и выдаёт категории:

| Категория | Смысл |
|---|---|
| Изменено существующее | у ID изменились формулировка, детали (трассировка, примечания), приоритет или теги; показано «было / стало» |
| Приоритеты проставлены впервые | массовая проставка приоритета, одна строка вместо шума |
| Новое | ID появились |
| Ушло из таблиц, но упомянуто в тексте | ID закрыты или перенесены в прозу (например «закрыты в ходе интервью») |
| Исчезло совсем | ID нет нигде в новой версии — самая тревожная категория |

## 3. Как подать изменения

Раздел «Что изменилось» состоит из четырёх блоков в таком порядке:

1. **Изменены существующие требования — главный блок.** Именно здесь аналитик теряет контекст, поэтому он первый и визуально выделен: заголовок с пометкой `⚠`, строка на каждый ID: `⚠ ID — было: … → стало: … — влияние на профиль: <раздел и что пересмотреть>`. Влияние на профиль формулируй для читателя своей роли; если изменение касается другого слоя, пиши «не влияет на профиль, см. Стыки» и всё равно покажи строку.
2. **Новые требования.** `ID — суть — раздел профиля, куда они вошли`.
3. **Закрытые или перенесённые.** Закрытые `OQ`/`R` с тем, как закрыты (из прозы BRD); исчезнувшие совсем — отдельным списком и вопросом в «Уточнить».
4. **Сняты неопределённости.** Если `[гипотеза]` стала `[подтверждено]` или `OQ` закрыт, перечисли: это меняет статус проектных решений, принятых по старой версии.

Для изменённых ID в профильных разделах и подразделе QA поставь пометку `⚠ изменено`: тестовые сценарии по ним нужно пересмотреть.

## 4. Что считать шумом

Скрипт видит текстовые различия, но не знает, что важно. Не включай в блок «Изменены» различия, которые не меняют смысл:

- замена имён людей в колонке владельца (`Анна` → `Олег`) — отметь одной строкой «заменены имена владельцев в OQ-…», без построчного вывода;
- перестановка фрагментов в примечаниях или нормализация пробелов, регистра, кавычек;
- «Достоверность» в виде отметки `[изменено vX.Y]` без изменения текста;
- массовая проставка приоритета (уже сжата скриптом).

Различие, которое меняет срок, сумму, условие, периметр, ответственного за систему, статус или приоритет существующего требования, — всегда существенно, даже если слов изменено мало. Сомневаешься — покажи строку.

## 5. Ограничения

Сравнение идёт по ID: если новая версия перенумеровала требования, скрипт покажет «исчезло» и «новое» вместо «изменено». Признак — много «исчезло совсем» при близком числе «новых»; скажи об этом пользователю и сопоставь по смыслу вручную, пометив сопоставление `[выведено]`.
