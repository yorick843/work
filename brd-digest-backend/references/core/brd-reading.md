# Как читать BRD по шаблону ba-requirements-interviewer

Версия ядра: 2

Файл общий для скиллов `brd-digest-*`: копии побайтово одинаковы. Правишь в одном месте — правь во всех и подними версию ядра (проверка — `check-skill.py` в режиме нескольких путей).

## Содержание

1. Карта секций BRD
2. ID и их формат
3. Теги достоверности
4. Что делать с неполным или чужим документом
5. Разбор «смешанных» требований

## 1. Карта секций BRD

| Секция | Что в ней | Куда идёт в выжимке |
|---|---|---|
| Шапка | юрлицо, масштаб, срок, статус, версия, журнал версий | «Суть доработки», версия документа |
| 1. Глоссарий | термины | как есть: расшифровывай термины в выжимке один раз |
| 2. Контекст и цели | проблема, цель, KPI | «Суть доработки», «Бизнес-смысл» |
| 3. Стейкхолдеры, 3.2 команды | кто владелец, какие ИТ-команды | «Владельцы» (кому адресовать вопросы) |
| 4. Пользователи и сегменты | для кого | «Бизнес-процессы» (если влияет на логику) |
| 5. Scope | в периметре / вне | «Границы» |
| 6.0 AS-IS | текущий процесс, не требования | «Бизнес-процессы», блок «было» |
| 6.1…6.N | требования `BR-NN` по подразделам | профильные разделы, по слою |
| 7. Интерфейс | UI-требования, подразделы по каналам | профиль `frontend` — основной источник; профиль `backend` берёт из неё только данные и правила, остальное — «Опущено» |
| 8. Тарифы и комиссии | расчёт, ставки | правила расчёта |
| 9. Регуляторика | норма, источник, статус | правила, ограничения, «Уточнить» |
| 10. Интеграции | система, направление, статус, владелец | интеграции |
| 11. NFR | `NFR-NN` | NFR |
| 12. Ограничения и риски | `C-NN`, `R-NN` | ограничения; риски с техническим следствием |
| 13. Критерии приёмки | `AC-NN`, цели и метрики | тестируемые критерии |
| 14. Трассировочные проверки | сироты, пустые цели | служебное; сироты — в «Уточнить» |
| 15. Открытые вопросы | `OQ-NN`, владелец, «блокирует scope» | «Уточнить» (блокирующие — первыми) |
| 16. Допущения | пронумерованный список без ID | «Уточнить», если допущение влияет на логику |
| 17. Готовность (DoR) | метрики и вердикт | одна строка в шапке выжимки |
| 18–19 | вопросы по ролям, следующие шаги | вопросы своей роли — в «Уточнить» |

Заголовки в конкретном BRD могут называться чуть иначе, номер секции — опорный.

## 2. ID и их формат

Шесть префиксов, номер двузначный и больше: `BR-01`, `NFR-01`, `AC-01`, `C-01`, `R-01`, `OQ-01`. ID определяется в первой ячейке строки таблицы; упоминание в другом месте — ссылка, а не определение. Диапазон `BR-18…BR-24` означает все ID между границами.

Эти правила закодированы в `scripts/brd_tools.py`; ручной разбор нужен только там, где скрипт сообщил, что не нашёл ID.

Зачем это важно: по ID выжимка связывается с источником, сравниваются версии и проверяется полнота. Выжимка без ID — пересказ, который нельзя проверить.

## 3. Теги достоверности

| Тег | Как передать в выжимке |
|---|---|
| `[подтверждено]` | без пометки: это норма по умолчанию |
| `[гипотеза]` | пометка `[гипотеза]` + в «Уточнить» |
| `[требует валидации: …]` | пометка с тем же адресатом + в «Уточнить» |
| `[требует кросс-валидации: роль]` | пометка + роль-адресат в «Уточнить» |
| `[со слов стейкхолдера]` | пометка `[со слов]`; это не подтверждено документально |
| `[зафиксировано под ответственность стейкхолдера]` | пометка; решение принято, но риск остаётся у стейкхолдера |
| `[AS-IS]` / `[TO-BE]` | различай «как есть» и «как будет»; в профильные разделы идёт TO-BE, AS-IS — в «Бизнес-процессы» |
| `[изменено vX.Y]` | служебная отметка правки; подсказывает, где искать изменение, но сравнение делай по тексту (`references/core/change-detection.md`) |

Причина: аналитик, получивший гипотезу без пометки, проектирует по ней как по факту. Пометка стоит одного слова, ошибка — переделки.

## 4. Что делать с неполным или чужим документом

- Нет ни одного ID по шаблону → `scripts/brd_tools.py` завершится с кодом 2 и сообщением. Скажи пользователю, что вход не BRD по шаблону, и остановись: выжимку из произвольного текста не строй (это отдельная задача без гарантий полноты).
- Секции отсутствуют (черновик, статус «требует дозаполнения») → делай выжимку из того, что есть; в начало поставь пометку «BRD неполный: нет секций …» и перенеси отсутствие в «Уточнить».
- Секция пустая или «не раскрывалась» (например, NFR «не раскрывались») → так и напиши в соответствующем разделе: «в BRD не раскрыто», не заполняй от себя.
- Две версии BRD → смотри `references/core/change-detection.md`.

## 5. Разбор «смешанных» требований

Одно `BR` может содержать и правило, и экран, и интеграцию. Не дроби требование молча:

1. Определи слой каждой части по правилам профиля.
2. В профильный раздел положи только свою часть, ID сохрани, часть другого слоя перенеси в «Стыки» со ссылкой на тот же ID.
3. Если слой определить нельзя, не угадывай: положи в «Стыки» с пометкой `[слой не определён]` и добавь вопрос в «Уточнить».

Причина: молчаливое дробление теряет ту часть, которая важна соседней роли; угаданный слой превращает вывод в выдумку.
