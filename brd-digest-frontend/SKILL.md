# BRD Digest — frontend

Превращает BRD по шаблону `ba-requirements-interviewer` в выжимку для фронтового аналитика (БА+СА) и фронтового тестировщика: только то, что есть в BRD, разложено по фронтовым слоям, с неопределённостью на виду.

## Когда применять, а когда нет

Применять: на входе готовый BRD (файл или текст) по шаблону; нужна выжимка под фронт; или даны две версии BRD и нужно показать, что изменилось.

Не применять:

- **Вход не BRD по шаблону** (письмо, постановка, чужой формат). Скрипт не найдёт ID и остановит работу: разбор опирается на ID, секции и теги шаблона. Скажи об этом и предложи собрать BRD через `ba-requirements-interviewer`.
- **Нужна выжимка для бека** (расчёты, интеграции, данные, статусы обработки): это `brd-digest-backend`.
- **Нужно сделать макет, прототип или дизайн**: выжимка не рисует и не проектирует; её цель — подготовить аналитика к постановке.
- **Нужно собрать или дополнить требования**: это `ba-requirements-interviewer`.

## Порядок работы

1. **Прими вход.** Запусти `python scripts/brd_tools.py ids <BRD>`. Код 2 означает «не BRD по шаблону»: остановись (см. выше). Количество ID по видам пригодится для шапки.
2. **Прочитай** `references/core/brd-reading.md` (карта секций, теги, смешанные требования) и `references/profile-frontend.md` (что относится к фронту, форматы разделов A–G, чек-листы пробелов).
3. **Прочитай** `references/core/digest-frame.md` (каркас, пометки, «Уточнить», подраздел QA, «Опущено»).
4. **Если даны две версии BRD:** прочитай `references/core/change-detection.md`, запусти `python scripts/brd_tools.py diff <старый> <новый>`; выжимка строится по новой версии.
5. **Составь выжимку** по каркасу. Начни с «Сути», «Бизнес-смысла» и «Бизнес-процессов», затем разделы A–G, «Стыки», «Уточнить», подраздел для тестировщика, «Опущено».
6. **Проверь полноту:** запусти `python scripts/brd_tools.py coverage <BRD> <выжимка>`; исправляй, пока потерянных и чужих ID нет.
7. **Сверься с источником:** выбери 5 строк из разных разделов, открой их в BRD и сравни смысл (формулировку, состав, условие, субъект).
8. **Выдай** файлом markdown, если пользователь не назвал другой канал; в ответе — 2–3 предложения о сути, число блокирующих неопределённостей и то, что нужно решить первым.

Если образец нужен, чтобы увидеть форму, прочитай `references/worked-example-frontend.md`.

| `scripts/selftest.py` | запусти после правок скилла |

## Принципы выжимки

Эти правила действуют на всех шагах; причина у каждого одна: выжимку берут как основу постановки, и всё, что в ней выглядит фактом, станет решением по макету и вёрстке.

- **Только BRD.** Строка выжимки несёт смысл строки BRD с её ID. Свой вывод помечай `[выведено]` и указывай, из каких ID он сделан; недостающее по чек-листу — `[пробел]`. Тексты, поля, состояния и форматы не придумывай; тексты из BRD переноси дословно.
- **Неопределённость в выдаче.** `[гипотеза]`, `[требует валидации]`, блокирующие `OQ` переносятся в профильные строки и собираются в «Уточнить» с адресатом: аналитик закроет их сам или через другие компетенции.
- **Слой по месту решения.** Фронт — всё, что пользователь видит и с чем взаимодействует; смешанное требование делится по слою, ID сохраняется, часть чужого слоя идёт в «Стыки».
- **Сначала смысл.** Разделы 1–3 читаются без профильных деталей: аналитик должен понять, о чём доработка, до того как погрузится в экраны.
- **Нет интерфейса — так и скажи.** Если BRD фронт не затрагивает (интеграционная задача, клиент пассивен), выжимка короткая: суть, процессы, что именно оставлено без доработок, стыки и вопросы. Не наполняй разделы A–G догадками.
- **Подраздел QA — часть выжимки.** Трассировка «требование → проверка», границы, данные, критерии; только из текста BRD.

## Чего не делать

| Антипаттерн | Признак опознания | Что делать |
|---|---|---|
| Придумать экран, поле или текст | в выжимке есть элемент, формат или формулировка, которых нет в BRD, и нет `[выведено]` | оставь `[пробел]` и вопрос в «Уточнить» |
| Сгладить неопределённость | у требования в BRD `[гипотеза]` или ссылка на `OQ`, а в выжимке строка без пометки | перенеси пометку и ссылку |
| Потерять ID | `coverage` показывает потерянные | добавь ID в раздел или в «Опущено» с причиной |
| Тихо опустить смешанное требование | ID есть в BRD с и экраном, и правилом, а в выжимке только одна часть без «Стыков» | запиши вторую часть в «Стыки» |
| Выдать выжимку по не-BRD | `ids` вернул код 2, но выжимка всё равно написана | остановись и объясни |
| Перефразировать обязательный текст | формулировка из BRD изменена, хотя она задана нормой или решением | перенеси дословно с указанием источника |
| Сравнить версии без ID | в режиме diff много «исчезло» и «новое» при перенумерации | скажи пользователю, сопоставь по смыслу с пометкой `[выведено]` |
| Показать шум как изменение | в «Изменены» только замена имён или пробелов | убери по правилам шума в `references/core/change-detection.md` |
| Рисовать макет или писать вёрстку | в ответе макет, компоненты, код | верни выжимку, предложи отдельную задачу |

## Проверка перед выдачей

- [ ] `coverage` завершился без потерянных и чужих ID.
- [ ] Порядок разделов совпадает с каркасом; пустой раздел содержит «в BRD не раскрыто».
- [ ] Каждый `[гипотеза]`, `[требует валидации]` и блокирующий `OQ` BRD виден в «Уточнить» с адресатом.
- [ ] Каждая строка «Уточнить» имеет ID-источник или пометку `[пробел]`.
- [ ] В выжимке нет полей, состояний, текстов и форматов, которых нет в BRD, кроме строк с `[выведено]`; тексты из BRD дословны.
- [ ] У каждого `BR` подраздела 7.1 есть уровень проверяемости; требования, зависящие от `OQ`, не помечены как `проверяется`.
- [ ] При двух версиях: блок «Изменены существующие требования» стоит первым, строки с `⚠`, шум убран.
- [ ] Сверка пяти строк с источником выполнена.

| Утверждение | На чём стоит | Что его отменит |

| Разбор по ID и префиксам BR/NFR/AC/C/R/OQ | шаблон `ba-requirements-interviewer` | смена шаблона BRD: правь `scripts/brd_tools.py` и `references/core/brd-reading.md` |

| Чек-листы пробелов фронта | типовые вопросы аналитика к экранам и состояниям | практика команды: дополни по итогам реальных выжимок |
| Ядро `references/core/` общее с `brd-digest-backend` | требование одинакового чтения BRD | расхождение копий — сверь версию ядра и перенеси правку |
