# Образец выжимки frontend (проверка формата, не источник фактов)

Образец построен на вымышленном BRD (версия 1.0) о перераспределении партнёрского кешбэка; компании, люди, даты и объёмы придуманы. Это BRD с минимальным интерфейсом: клиент пассивен, интерфейс затрагивают только внутренние роли. Поэтому образец показывает ещё и то, как выглядит короткая фронтовая выжимка и как оформляется «в BRD не раскрыто». Факты в новую выжимку берутся только из BRD пользователя.

# Выжимка для фронтового аналитика: перераспределение партнёрского кешбэка

**BRD:** v1.0 от 15.01.2030 · **Статус:** требует дозаполнения (7 блокирующих OQ) · **Читатель:** frontend (БА+СА), фронтовый тестировщик
**Охват:** 74 ID в BRD, все учтены (проверено `scripts/brd_tools.py coverage`): в разделах A–G, в «Стыках» или в «Опущено»
**Важно:** интерфейс затрагивается только для внутренних ролей, и описан он тонко (секция 7 — два абзаца). Клиентские каналы доработок не получают.

## 1. Суть доработки

Процесс перераспределения кешбэка по партнёрским акциям переводится на новую логику: реестр строится по фактическому балансу партнёра, выплата идёт на счёт партнёра, затем кешбэк автоматически перераспределяется клиентам. Для фронта это не новые экраны, а доработка вкладки контроля в Back Office для операционного контроля и отчётов. Срок — 01.07.2030.

## 2. Бизнес-смысл

Приведение процесса к новой редакции оферты. После запуска операционный контроль проверяет каждый реестр перераспределения; для этого ему нужны вкладка и отчёт. Клиент в процессе пассивен, его отображение не меняется.

## 3. Бизнес-процессы

| Было (AS-IS) | Станет (TO-BE) |
|---|---|
| Контроль — вкладка в Back Office; детализированный отчёт в BI (в разработке); обращения клиентов → задача в таск-трекере → расследование операционным контролем | Вкладка Back Office дорабатывается (BR-06, BR-09); отчёт в BI остаётся в разработке (BR-22); партнёр получает отдельный отчёт с номером акции (BR-08, BR-13) |

Участники интерфейса: операционный контроль (основной пользователь вкладки и отчёта), финансовый контроль (проверка, BR-07), сотрудники партнёра (получают отчёт), клиентский сервис (заводит задачи в таск-трекере).

## 4. Профильные разделы

### A. Сценарии и навигация

| Роль | Сценарий (по BRD) | ID |
|---|---|---|
| Операционный контроль | пост-контроль реестров на отдельной вкладке Back Office; проверка каждого реестра целиком, без построчной проверки клиентов | BR-06, BR-09, BR-34 |
| Операционный контроль | расследование обращений из таск-трекера | BR-23 |
| Партнёр | сверка оборотов по отчёту (выгрузке) от брокера | BR-08, BR-24 |
| Клиент | пассивен; каналы не затрагиваются | BR-29 |

Точка входа и навигация в BRD не описаны `[пробел]`.

### B. Экраны, элементы и действия

| Экран / элемент | Что показывает или позволяет | Статус | ID |
|---|---|---|---|
| Вкладка Back Office «контроль перераспределения» | контроль реестров операционным контролем; состав агрегатов `[гипотеза]`, кросс-валидация: операционный контроль | доработка | BR-06, BR-09 |
| Отчёт в BI | детализированный отчёт по реестрам и выплатам для операционного контроля | в разработке, внедрение к 01.07.2030; запуск не блокирует | BR-22, AC-03 |
| Отчёт для партнёра | сверка оборотов; содержит номер акции, без клиентских данных | существует / доработка `[гипотеза]` | BR-08, BR-13 |
| Отображение у клиента (брокерский отчёт, мобильное приложение, личный кабинет) | операция как «кешбэк по партнёрской акции» | без изменений | BR-29 |

Доступные действия (сортировка, фильтры, экспорт) в BRD не раскрыты `[пробел]`.

### C. Данные на экране

В BRD названы только:

| Поле / показатель | Откуда | Формат и обязательность | ID |
|---|---|---|---|
| Агрегаты реестра: сходимость сумм, контрольные показатели | реестр перераспределения | состав `[гипотеза]` | BR-09 |
| Номер акции в отчёте партнёра | — | клиентских данных нет | BR-13 |

`[пробел]`: формат, единицы, округление сумм, обязательность полей, источник данных вкладки.

### D. Состояния и видимость

Видимость: вкладка — для операционного контроля; финансовый контроль проверяет удержание сбора (BR-07); партнёр видит только свой отчёт (BR-08). Что видит недоступный пользователь, в BRD не раскрыто `[пробел]`. Состояния (пустое, загрузка, ошибка, частичные данные) не раскрыты `[пробел]`. Выкатка: отчёт в BI не блокирует запуск (AC-03); пилот и усиленный контроль первого прогона не предусмотрены (AC-04).

### E. Тексты и сообщения

| Где | Текст / название (дословно) | Источник формулировки | ID |
|---|---|---|---|
| Брокерский отчёт, мобильное приложение, личный кабинет | «кешбэк по партнёрской акции» | решение брокера; финансовый контроль согласовал | BR-29 |

Тексты уведомлений не требуются: отдельное уведомление клиентов вне периметра.

### F. NFR и каналы

Каналы: клиентские каналы не меняются; внутренние — Back Office и BI. Доступность, локализация, производительность отображения, события аналитики в BRD не раскрыты `[пробел]`. Нагрузка (несколько реестров в день, сотни клиентов в каждом) — NFR-02: для вкладки это источник требований к объёму данных на экране, но в BRD отдельного требования нет `[пробел]`.

### G. Тестируемые критерии интерфейса

| ID | Критерий | Как наблюдается | Уровень |
|---|---|---|---|
| BR-13 | отчёт для партнёра не содержит клиентских данных | просмотр содержимого отчёта | проверяется |
| BR-29 | отображение операции у клиента не изменилось | сравнение с текущим поведением | проверяется |
| AC-03 | отсутствие отчёта в BI запуск не блокирует | запуск без отчёта | проверяется |
| AC-02 | демо сотрудникам расчётного центра, операционного контроля и финансового контроля | факт проведения | проверяется |
| BR-09 | вкладка позволяет проверить реестр целиком | состав агрегатов | не проверяется (состав `[гипотеза]`) |

## 7. Для тестировщика

### 7.1 Трассировка «требование → проверка»

| ID | Проверка | Уровень |
|---|---|---|
| BR-13 | Given отчёт для партнёра; When формируется; Then в нём номер акции и нет клиентских данных | проверяется |
| BR-29 | Given операция перераспределения; When клиент открывает отчёт, приложение, кабинет; Then название «кешбэк по партнёрской акции», как раньше | проверяется |
| BR-06 | Given вкладка контроля; When операционный контроль открывает; Then перераспределение доступно для контроля | частично (макет и действия не описаны) |
| BR-09 | Given реестр; When операционный контроль проверяет; Then видны сходимость сумм и контрольные показатели | частично (состав `[гипотеза]`) |
| BR-22 | Given отчёт в BI; When операционный контроль открывает; Then детализация по реестрам и выплатам | частично (внедрение к 01.07.2030, не блокирует запуск) |

### 7.2 Граничные случаи

| ID | Граница | Что проверить |
|---|---|---|
| BR-09 | реестр с нулевой суммой, очень большой реестр (NFR-02) | вкладка корректно показывает итоги `[выведено]` |
| BR-13 | акция без клиентских данных | в отчёте остаётся только номер акции |
| BR-22 | отчёта нет к моменту запуска | запуск не блокируется (AC-03) |

### 7.3 Тестовые данные

Реестры разного размера (нормальный, большой, с нулевой суммой); акции для отчёта партнёра; пользователи ролей: операционный контроль, финансовый контроль; клиент с зачисленным кешбэком для проверки отображения (BR-29).

### 7.4 Критерии приёмки

AC-02, AC-03, AC-04 — см. раздел G и «Опущено». У BR-06, BR-09, BR-22 отдельных критериев приёмки интерфейса нет.

## 8. Опущено

Бековая логика, интеграции, сбори, ошибки и данные — задача выжимки для бека; здесь не нужны, кроме стыков: BR-01, BR-02, BR-03, BR-04, BR-05, BR-10, BR-11, BR-14, BR-15, BR-16, BR-17, BR-25, BR-26, BR-27, BR-28, BR-32 — логика и сбори · BR-12, BR-20 — процесс и сроки перераспределения · BR-35 — согласование корректировок, не интерфейс · BR-23, BR-24 — вошли в A как сценарии · NFR-01, NFR-03 — срок исправления и журналирование · C-01, C-02, C-03, C-04, C-05, C-06, C-07, C-08 — ограничения сроков, ресурсов, регламента, контракта · R-01, R-03, R-05, R-06, R-07, R-08, R-09, R-10, R-12, R-14, R-15, R-18, R-20, R-21, R-23 — риски логики, сроков и контроля · AC-01 — ИФТ, не интерфейс · OQ-01, OQ-08, OQ-13, OQ-14, OQ-15, OQ-16, OQ-17 — вопросы сборов, процесса и бюджета без влияния на экран.
